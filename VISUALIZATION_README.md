# RealSense RGBD Visualization Guide

This guide shows how to visualize RealSense camera data and pose information in RViz.

## What Gets Visualized

- **PointCloud**: 3D colored pointcloud from RealSense native output
- **RGB Image**: Live color camera feed
- **Pose 2D Overlay**: 2D human pose keypoints and skeleton overlayed on RGB image
- **Pose 3D**: Human pose data from `/uq/pose_3d` topic (displayed as pose arrows)

## Prerequisites

Make sure your RealSense camera is publishing data on these topics:
- `/realsense/camera_1/depth/color/points` - Native RealSense pointcloud
- `/realsense/camera_1/color/image_raw` - RGB image
- `/uq/pose_2d` - 2D pose keypoints (uq_msgs/Pose2D)
- `/uq/pose_3d` - 3D pose data (PoseArray)

Ensure pointcloud is enabled in your RealSense camera parameters.

## Building

```bash
# From workspace root
colcon build --packages-select realsense_rgbd_streamer
source install/setup.bash
```

## Usage

### Option 1: Simple Launch (Recommended)

Launch RViz with minimal configuration:

```bash
ros2 launch realsense_rgbd_streamer viz_simple.launch.py
```

This uses `camera_1_link` as the fixed frame and should work reliably.

### Option 2: Full Configuration Launch

Launch RViz with full configuration:

```bash
ros2 launch realsense_rgbd_streamer visualization.launch.py
```

This uses `camera_1_color_optical_frame` as the fixed frame.

### Option 3: Manual Launch

Open RViz with a config file:

```bash
# Minimal config
rviz2 -d $(ros2 pkg prefix realsense_rgbd_streamer)/share/realsense_rgbd_streamer/config/visualization_minimal.rviz

# Full config
rviz2 -d $(ros2 pkg prefix realsense_rgbd_streamer)/share/realsense_rgbd_streamer/config/visualization.rviz
```

Or start RViz without config and manually add displays for the topics.

## Topics Visualized

- `/realsense/camera_1/depth/color/points` - Colored 3D pointcloud (PointCloud2)
- `/realsense/camera_1/color/image_raw` - RGB camera feed (Image)
- `/uq/pose_2d_overlay` - RGB image with 2D pose overlay (Image) - Generated by pose_2d_overlay node
- `/uq/pose_3d` - Human pose data (PoseArray)

## Nodes

### pose_2d_overlay
This node subscribes to:
- `/realsense/camera_1/color/image_raw` - RGB camera feed
- `/uq/pose_2d` - 2D pose keypoints

It draws the pose keypoints and skeleton connections on the RGB image and publishes to `/uq/pose_2d_overlay`.

**Keypoint format**: The node expects `/uq/pose_2d` to be a `uq_msgs/Pose2D` message with a `keypoints_2d` field in format `[x1, y1, x2, y2, ..., xn, yn]` where each (x, y) pair represents pixel coordinates of a keypoint. The overlay is only drawn when `human_detected` is `true`.

**Skeleton connections**: The node is configured for a 13-joint model:
```
0: Nose, 1: LShoulder, 2: RShoulder, 3: LElbow, 4: RElbow,
5: LWrist, 6: RWrist, 7: LHip, 8: RHip, 9: LKnee, 10: RKnee,
11: LAnkle, 12: RAnkle
```

See `POSE_2D_OVERLAY.md` for details on customizing the skeleton for different pose models.

To run the node standalone:
```bash
ros2 run realsense_rgbd_streamer pose_2d_overlay
```

## RViz Configuration

The RViz config includes:
- **PointCloud2**: Displays the colored 3D pointcloud from RealSense
- **RGB Image**: Shows live RGB camera feed in a separate panel
- **Pose 2D Overlay**: Shows RGB image with 2D pose keypoints and skeleton drawn on top
- **Pose3D**: Visualizes 3D pose data as arrows in the 3D view

### Frame

All data is displayed relative to the `camera_1_link` frame.

## Troubleshooting

**No pointcloud appears:**
- Verify pointcloud is being published: `ros2 topic hz /realsense/camera_1/depth/color/points`
- Check your RealSense camera configuration has pointcloud enabled
- Verify the topic name matches your camera namespace

**RGB image not showing:**
- Check color image is publishing: `ros2 topic hz /realsense/camera_1/color/image_raw`
- Try clicking on the Image panel to refresh it

**Pose data not showing:**
- Confirm pose data is publishing: `ros2 topic echo /uq/pose_3d`
- Verify the message type is `geometry_msgs/PoseArray`

**Frame errors in RViz:**
- Check available frames: `ros2 run tf2_ros tf2_echo camera_1_link camera_1_color_optical_frame`
- Adjust the Fixed Frame in RViz Global Options if your camera uses a different frame name

**Pose 2D overlay not showing or incorrect:**
- Verify `/uq/pose_2d` is publishing: `ros2 topic echo /uq/pose_2d`
- Check the keypoint format matches `[x1, y1, x2, y2, ...]` in pixel coordinates
- Verify the `pose_2d_overlay` node is running: `ros2 node list | grep pose_2d_overlay`
- Check the skeleton connections in `pose_2d_overlay.py` match your pose model's keypoint ordering
- Invalid keypoints (x<=0 or y<=0) are automatically skipped

**Performance issues:**
- Reduce pointcloud density in your RealSense camera parameters
- Lower the camera frame rate
- Close image panels if not needed
- Disable the pose_2d_overlay node if you don't need the 2D pose visualization
